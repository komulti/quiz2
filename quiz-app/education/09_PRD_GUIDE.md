# PRD (Product Requirements Document) 작성 가이드

> PRD는 프로젝트의 **첫 번째 문서**이자 Claude Code와의 **첫 대화**다.
> 잘 쓴 PRD 하나가 프로젝트 방향 전체를 결정한다.

---

## PRD가 필요한 이유

### CLAUDE.md와의 차이

| | PRD | CLAUDE.md |
|---|-----|-----------|
| **시점** | 프로젝트 시작 전 | 프로젝트 진행 중 |
| **내용** | 무엇을, 왜 만드는가 | 어떻게 만드는가 |
| **독자** | 나 자신 + Claude | Claude |
| **변경** | 거의 안 바뀜 | 자주 업데이트 |
| **목적** | 방향 설정 | 규칙/컨벤션 |

```
PRD: "무엇을 만들 것인가" (What & Why)
  ↓
CLAUDE.md: "어떻게 만들 것인가" (How)
  ↓
Plan 파일: "구체적으로 어떤 순서로" (Step by Step)
```

### Claude Code와의 관계

PRD를 먼저 작성하고 Claude에게 보여주면:
1. Claude가 **전체 맥락**을 이해한 상태에서 작업
2. "이 기능은 왜 필요한가?"에 대한 판단 근거 확보
3. 기능 간 **우선순위**를 스스로 판단 가능
4. 불필요한 기능 제안을 줄임

```
  ↓

```

## PRD 템플릿

```markdown
# [프로젝트 이름] PRD

## 1. 개요
### 한줄 요약
[이 프로젝트가 무엇인지 한 문장으로]

### 배경
[왜 이것을 만드는가? 어떤 문제를 해결하는가?]

### 목표
[성공하면 어떤 상태가 되는가?]

## 2. 타겟 사용자
[누가 이 앱을 쓰는가? 어떤 상황에서?]

## 3. 핵심 기능
### P0 (필수 - MVP에 포함)
- [기능 1]: [설명]
- [기능 2]: [설명]

### P1 (중요 - MVP 직후)
- [기능 3]: [설명]

### P2 (있으면 좋음 - 나중에)
- [기능 4]: [설명]

## 4. 사용자 흐름
[주요 시나리오를 순서대로 설명]

## 5. 기술 요구사항
- 플랫폼: [웹/모바일/데스크톱]
- 성능: [로딩 시간, 응답 속도]
- 호환성: [지원 브라우저/기기]

## 6. 데이터
[어떤 데이터가 필요한가? 어디서 오는가?]

## 7. 비기능 요구사항
- 오프라인 지원 여부
- 다국어 지원 여부
- 접근성 요구사항

## 8. 마일스톤
[대략적인 일정 또는 단계]
```

## PRD를 Claude Code에 활용하는 방법

### 방법 1: 프로젝트 루트에 PRD.md 파일로 저장

```
quiz2/
  ├── PRD.md          ← Claude가 자동으로는 안 읽지만 참조 가능
  ├── CLAUDE.md       ← 자동으로 읽음
  └── quiz-app/
```

### 방법 2: CLAUDE.md에 PRD 요약 포함

```markdown
# CLAUDE.md

## 프로젝트 개요
(PRD에서 핵심만 발췌)

## 기술 스택
...
```

### 방법 3: 첫 대화에서 PRD 전달

```
"이 PRD를 읽고 프로젝트를 시작하자.
 PRD.md 파일을 읽어줘. 그리고 이걸 바탕으로 CLAUDE.md를 작성해줘."
```

> **추천**: 방법 1 + 방법 3 조합. PRD.md 파일로 저장 + 첫 대화에서 읽게 하기.

## PRD 작성 팁

### 1. 완벽하지 않아도 된다
```
Day 0에 작성한 PRD가 100% 맞을 필요 없다.
개발하면서 바뀌는 부분이 있으면 PRD도 업데이트.
핵심은 "시작 전에 방향을 잡는 것".
```

### 2. P0/P1/P2 우선순위가 핵심
```
모든 기능이 중요하다고 적으면 아무것도 중요하지 않은 것과 같다.
P0만 있어도 동작하는 앱이 되어야 한다.
```

### 3. 사용자 흐름을 구체적으로
```
# Bad
"사용자가 퀴즈를 풀 수 있다"

# Good
"사용자가 메인 화면에서 과목을 선택하고,
 출제 모드(랜덤/년도별)를 고르고,
 문제 수를 설정하고,
 '시작' 버튼을 누르면 퀴즈가 시작된다.
 각 문제에서 4개 선택지 중 하나를 탭하면
 즉시 정답/오답 피드백이 표시된다."
```

### 4. "비기능" 요구사항을 잊지 말기
```
기능만 적고 이런 것들을 빼먹으면 나중에 대공사:
- 오프라인 지원 → PWA 설정이 완전히 다름
- 모바일 최적화 → CSS 아키텍처가 바뀜
- 클라우드 동기화 → 상태 관리 설계가 달라짐
```

### 5. Claude에게 PRD 검토 요청

```
"이 PRD를 검토해줘. 빠진 부분이 있는지,
 기술적으로 어려운 부분이 있는지 의견을 줘"
```

```
  "HashRouter (GitHub Pages)"

Plan: Stage 1 (Day 1)
  "프로젝트 생성 + 기본 설정 + 데이터 파이프라인"
    ↓

Plan: Stage 2 (Day 2-3)
  "타입 → 스토어 → 메인 → 설정 → 퀴즈 → 결과"
    ↓
  ... (단계적 진행)
```
